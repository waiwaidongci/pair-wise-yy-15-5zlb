# 赛鸽训放 · 离线航迹可信度复测台

面向赛鸽棚的纯前端（离线）航迹可信度复测工具。每羽赛鸽按 **足环号 × 放飞时刻 × 放飞地点** 形成唯一赛程，
对多段鸽钟报时做逐段矛盾筛查，并由两名复核人双票解冻争议。

## 复测规则

- **逐段筛查三类矛盾**（从放飞点起逐段推进）：
  - 报时时刻未严格递增（校准后仍回退）
  - 分段速度超过该赛程限速（按累计航距 / 校准后段耗时）
  - 累计航距回退；累计航距增量与地理位移（haversine）明显不符
- **连续可信段**：遇到第一个矛盾段即截断；只有连续可信段到达归巢巢门点才计归巢并进入可信排行。
- **争议段不计未归巢**：矛盾段及其后报点全部冻结，既不进排行，也不计入"未归巢"提醒；
  只有无任何矛盾但归巢点未报时的赛程才算"在飞未归巢"。
- **双人复核解冻**：两名复核人各交一档置信度（高/低）+ 必填原因；
  - 同高 → 争议段解冻采信，按全程重算均速重入排行
  - 同低 → 维持争议段不计
  - 不一致 → 保持冻结待议
  - 同一争议签名重复提请沿用首条记录（首次提请时间保留）
- **变更即失效重算**：放飞地时区、放飞时刻/地点、逐点鸽钟校准、任一报点数据变化都会改变赛程参数签名，
  排行、风险徽章、配对提示与复核结论立即失效；失效的复核自动转入"旧版只读"留痕，不可回改。
  足环档案（血统/配对）变化通过独立的档案签名使配对提示重算。
- **离线持久化**：全部数据存 localStorage（`pigeon-retest-v2`），刷新后赛程、争议队列与时间轴保持一致；
  可手动封存只读版本。时区换算使用 `Intl.DateTimeFormat`，无任何网络依赖。

## 技术栈

React 19 + Vite + TypeScript（无第三方运行时依赖）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62014
